## 总控核实

E（PR #72）把 OneDragon 的释放改为单一路径；等待/事件失败与释放同时失败时保留首个异常，尝试记录 Blocked/Unconfirmed。最终释放失败不能提前记录 Confirmed，也不能解除安装占用；外层 handoffClean 仍为 false，桌面恢复标记保留。成功路径仍需 Reconcile、事件消费、Dispose 均完成后才发布终态。作者故障测试覆盖正常取消、日志失败、日志+释放双故障以及终态记录失败。

D（PR #75）补上 BetterGI 最终释放后的确认。`CleanupConfirmedAfterDisposal` 默认 false，直到释放完成并通知 registry 后才根据清理事实赋值；外部 finally 在 try 内的 await using 结束后读取该值。释放失败时保留配置恢复文件、原生恢复标记与桌面阻断。测试使用实际多账号编排、原生事务核心、BetterGiRun 和记录路径，成功对照可进入第二账号，失败只进入首账号。正常取消可以在已确认清理后恢复配置，同时编排仍停止后续账号；不采纳“取消必须视作清理失败”的错误建议。

## 审查轮次与开放残余

- E：有效首审与唯一复审各1轮；首审确认的异常遮蔽和重复释放已修复。复审仍指出原有 EngineStartException 终态日志写入失败会遮蔽启动诊断；总控核对源码，日志异常仍向外传播且桌面标记不清除，不会产生错误成功或继续下一账号。另外，迟到日志任务可能仍存活。允许该安全改进进入集成分支，但不标 E 整体独立审查无问题或发布通过。
- D：实现首审+复审2轮，另有此前文档审计1轮，不混计或重复审 E。两轮意见与源码/四组合边界测试核实后，无已确认的新增未修复缺陷。D-2 的 Finished 与 cleanup 未确认组合仍为既有低优先级终态一致性残余；CleanupConfirmed=false 继续阻断编排，不等于执行放行。
- 原始审查和逐项处置分别保存在 `docs/parallel/furina-e-status.md`、`furina-d-status.md`。总控未追加第三轮、未把模型原文的全部指控直接当成事实，也未把实际残余隐去。
