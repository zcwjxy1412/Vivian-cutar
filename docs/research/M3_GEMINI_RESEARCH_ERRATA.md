# Gemini M3 研究纠错与接入边界

本文件与四份 Gemini 原始研究并列保存。原文保持原样，以下更正不代表发行包或真实游戏已经实测。原文中的 A/B/C/D 证据等级和 Pending 标记仍需按实际证据逐项核验。

## 1. March7thAssistant 的提交时序

原始《上游发行包验证报告》§1.3 和《适配器开发技术规约》§4 提出了“若 6350047 晚于 v2026.10.31，则该版可能没有 m7a.exe”的条件分支；《CLI 兼容性报告》也把两个提交并列，易使读者误读为标签之后才加入构建定义。

- v2026.10.31 的标签提交为 `1e77d59`；引入 m7a 构建定义的 `6350047` 是其祖先。
- 固定到该标签的 `March7th Assistant.spec` 已包含 m7a 构建定义。因此**不能**以“6350047 晚于正式标签”为由断定正式版缺少 `m7a.exe`，也不能据此自动回退到需要不同权限的 `March7th Assistant.exe`。
- 标签源码存在构建定义仍不证明发行压缩包实际包含该文件。官方归档字节校验、解包清单与可执行文件行为均为 **Pending**。PR #26 的发行资产元数据和合成 ZIP 测试不能替代官方实包验收。

## 2. 进程归属与权限

《进程拓扑与权限风险分析》§4 的“VIvian 宿主与引擎同级管理员运行”及 §5 的“按安装路径与游戏进程名兜底清扫”，不能直接转为产品行为。《适配器开发技术规约》§4 的“在管理员权限下启动三引擎”是待授权的桌面验证步骤，不是默认运行策略。

- VIvian 保持最小权限；任何 UAC 请求须由用户明确授权，拒绝或跨权限启动应保守阻断。不得绕过 UAC 或反作弊。
- 只通过 VIvian 持有的具体进程/Job 句柄及 RunId 归属执行终止。不得按游戏进程名杀进程，也不得扫描安装路径后批量终止身份未知的进程；同名的用户原有进程必须保持不受影响。
- Job Object 中计数为零只说明**该 Job 边界**内没有活动进程，不证明经 UAC、任务计划程序、启动器或其他渠道脱离该 Job 的资源已经清理。对跨权限与脱离边界的身份无法确认时，保持 Cleanup=Unconfirmed，阻断后续任务。
- 未验证的可执行文件、权限等级或后备入口不得自动回退。三款引擎的进程拓扑和权限边界分别实测，不从一款推断另外两款。

## 3. 发行资产与 CLI 的证据等级

四份原始报告明确声明没有下载并重算三款引擎完整官方归档；其中的发行元数据、源码推断、网站描述和合成样本测试应分别记录，不能合并为“发行包已验证”。请以对应版本的官方源码、Release 元数据、**实际官方资产哈希与解包内容**建立独立证据链，未经实测保持 Pending。

源码定义 `--status`、`--list --json` 或其他参数，不等于正式发行二进制可正常调用。March7thAssistant 的 `--status` 可能创建/删除写权限探测文件，或触发配置初始化；它不是严格无写入的只读查询。只能在隔离副本中记录调用前后的文件差异，不得未经授权触碰用户上游原始配置。退出码 0、关键词或进程退出本身都不是充分的任务完成证据。

## 4. 与 VIvian 当前实现对照

生产适配器必须遵循 VIvian 真实的 `IGameAdapter`、`IEngineRun`、`IProcessSupervisor` 和调度器状态机，不可直接照搬研究报告的接口示例。当前真实引擎准入仍被阻断；PR #30 的 RunId 启动门禁与 PR #20 的同步停止组合尚待独立复审，不能以 CI 通过代替权限、清理或发行包验收。桌面 UAC 和真实游戏账号操作均为 Pending，须另行授权。
