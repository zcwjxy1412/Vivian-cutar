# VIvian M5.2 自动账号切换 · 候选版说明

> 状态：**开发完成候选版，真机验收未完成**。本版本已有代码实现、Linux 交叉编译与自动化测试。下列项目仍需在 Windows 真机上验证，验证前都不能视为已通过：Windows 完整回归、扫描按钮实机、A→B 双账号实机、UAC 拒绝/异常路径。

## 一、怎么启动

1. 解压 `VIvian-M5.2-AutoSwitch-win-x64.zip` 到一个**新的空文件夹**（不要覆盖旧版本文件夹，旧版本可直接作为回滚包）。
2. 双击 `VIvian.exe`。
3. 数据目录沿用 `%LOCALAPPDATA%\VIvian-M5-DailyTest`：已有账号、配置和历史都会保留。本版本**没有修改数据库结构**（仍为 v6），因此不会触发迁移；历史迁移备份 `*.pre-v*.bak` 保持原样。

## 二、扫描登录账号

1. 打开星铁，停在米哈游登录界面，确保能看到已保存的手机号。
2. 在 VIvian「账号管理」点「扫描登录账号」。
3. VIvian 会**暂时最小化自己**，截取游戏窗口后再恢复。截图只在本机做 OCR，不上传，也不保存含账号的原图。
4. 截图前会核对窗口身份：必须属于 `StarRail.exe`，且客户区内 9 个校验点都属于游戏窗口。只要有一个点被其他窗口（包括 VIvian 自己）挡住，这次截图就会被拒绝，并提示是谁挡住了游戏。
5. 失败时会给出具体原因，常见处理：
   - 「游戏窗口处于最小化」：在任务栏点开游戏后重试；
   - 「被……遮挡」：把游戏切到前台后重试；
   - 「画面为全黑」：把游戏切到窗口或无边框模式；
   - 「没有已保存账号」：先在游戏里手动登录一次，并勾选记住账号。
6. 每次扫描（成功或失败）都会写入扫描记录：窗口句柄、进程号、客户区尺寸、截图时间、截取方式、校验点结果，以及每个账号的脱敏手机号、坐标和置信度。

## 三、自动 A→B 批次

勾选账号、选择统一或独立配置，然后点「运行选中账号」，确认一次即可。之后流程如下：

1. **回到账号选择界面**：结束 VIvian 能证明身份的星铁进程（核对进程号和启动时间），重新启动游戏。自动登录后的标题页会点「退出登录」并确认。**这里绝不会点「点击进入」**，因为那样会用上一个账号进入游戏。
2. **选择账号**：展开已保存账号列表，点中目标账号。之后必须看到收起的登录卡片**只显示目标账号**，才会继续按「进入游戏」。
3. **进入游戏**：按「点击进入」并确认进入游戏世界。如果读到 UID，会额外核对两点：与档案记录一致；与上一个账号不同。
4. **执行与清理**：执行星铁日常。只有在任务进程清理确认、临时配置恢复之后，才会切换到下一个账号。
5. 每个账号都会写一条脱敏切换证据（`account_switch_history.detail`），内容包括：目标账号、上一个账号、确认选中的时间、按「进入游戏」的时间、通过标题页的时间、进入世界的时间、经过的界面轨迹、脱敏 UID，以及判定结果（`verified` 或 `mismatch`）。

**以下情况会立即停止整个批次**，不会在不确定的账号上继续执行：

- 出现验证码、密码、滑块、实名或用户协议，这些需要本人处理；
- 无法确认选中的是目标账号，或 UID 与上一个账号相同；
- 选完账号后游戏进程发生变化；
- 连续识别不出画面（只等待，不盲点）；
- 同一画面点击后没有反应（每个画面最多点 3 次）；
- 任务清理或配置恢复没有得到确认；
- 管理员授权被拒绝或取消，或输入宿主断开。

目标账号不在已保存列表里时，只跳过该账号。这时还没有进入任何账号，游戏仍停在账号列表。

## 四、管理员授权（UAC）

- 游戏以管理员权限运行，所以需要一个管理员输入宿主来点击游戏。**每个批次最多弹一次 UAC**，同一批次内所有账号都复用这个宿主。
- 拒绝或关闭 UAC 窗口时，批次停止并记录为 `uac_refused`，**本批次不会再次弹窗**。重新开始一个批次才会再次请求授权。
- 宿主崩溃或连接中断时，记为 `input_host_unavailable`，批次停止，不会自动重弹，也不会退回到普通权限去点击。
- 批次结束时会关闭宿主，并按启动时拿到的进程句柄核实它已经退出。如果无法核实，批次不会显示为「完成」，并会提示到任务管理器检查残留的 VIvian 进程。
- 批次详情会写明本批次请求授权的次数。

## 五、本次改动

| 模块 | 说明 |
| --- | --- |
| `Core/Accounts/LoginFlow.cs`（新增） | 登录界面状态分类、目标驱动状态机（含步数、点击次数、未知画面上限）、切换证据判定、截图归属判定 |
| `StarRailLoginDriver` | 改由状态机驱动。删除「标题页直接点击进入」和「未知画面点屏幕中央」两条路径；新增退出登录、选中确认、会话连续性校验 |
| `ElevatedInputHost` | 引入批次会话（每批一次 UAC），失败分类为拒绝、超时、断开、失败，同一批次不会重复弹窗；结束游戏时携带进程启动时间 |
| `ScreenCapture` / `LoginScreenReader` | 截图不再把游戏设为永久置顶；BitBlt 截图需 9 点归属校验；记录扫描证据 |
| `MultiAccountOrchestrator` | 管理批次的 UAC 会话；把前一账号的身份传给下一账号做对比；致命失败停止整批；写入切换证据；宿主退出未核实时不报完成 |
| 扫描按钮 | 扫描期间最小化 VIvian，状态栏显示窗口身份和校验结果 |
| 进程身份 | 结束星铁时核对进程号和启动时间，防止 PID 被复用后误结束 |
| CI / 脚本 | `Build-M5_2Test.ps1`、`Test-M5_2Local.cmd`（固定本地入口），`windows.yml` 增加 M5.2 打包与测试结果上传 |

## 六、已知限制（真实状态）

- 「退出登录」按钮的文字（`退出登录`、`登出`、`切换账号`、`注销登录`）**尚未在真机标题页确认**。如果识别不到，批次会停止并说明原因，不会改点「点击进入」。
- 双账号 A→B **未在真机实测**：历史上只有一个保存账号。需要在游戏登录界面再登录并记住第二个账号。
- 扫描按钮**未在真机上从 VIvian 界面实测成功**。
- Windows 下的完整回归、CI 和真实 UAC 拒绝/崩溃路径都需要在 Windows 上执行，Linux 结果不能替代。
- 没有读到 UID 时，身份判定只依据「登录卡片确认 + 会话连续」，报告中会注明。
