| 项目 | 内容 |
|---|---|
| 版本 | v1.0（审查基线） |
| 基准日 | 2026-11-03 |
| 适用发布 | VIvian V1.0（Windows 桌面，三引擎统一任务管理） |
| 关联文档 | `docs/reviews/ARCHITECTURE_REVIEW.md`、`docs/reviews/RISK_REGISTER.md`、`docs/acceptance/TEST_PLAN.md` |
| 门禁原则 | **顺序门禁 + 证据制**：前一道门未通过，不得进入下一道；任何"口头通过"无效 |

## 1. 门禁模型

```
G0 设计冻结 → G1 构建与供应链 → G2 自动化测试 → G3 状态机与失败恢复
   → G4 升级与回滚 → G5 安全 → G6 合规 → G7 实机人工验收 → G8 发布签署
```

| 门 | 名称 | 一句话通过条件 |
|---|---|---|
| G0 | 设计冻结 | Critical 架构缺陷全部关闭或有签署豁免；契约与版本矩阵冻结 |
| G1 | 构建与供应链 | 可复现构建、哈希/签名校验、SBOM、依赖锁定 |
| G2 | 自动化测试 | A 级用例 100% 通过；覆盖率达标 |
| G3 | 状态机与失败恢复 | 10 条核心迁移 + 假成功回归 + 崩溃恢复全绿 |
| G4 | 升级与回滚 | 升级、断电中断、回滚、回滚后再升级全部通过 |
| G5 | 安全 | 威胁模型闭环；穿越/注入/提权/供应链用例全绿 |
| G6 | 合规 | 许可证与分发模式闭环；法务签字 |
| G7 | 实机人工验收 | MA-01~MA-12 全部通过 |
| G8 | 发布签署 | RC 清单、回滚预案、灰度与支持就绪 |

## 2. 阻断发布的严重缺陷类型

> 只要存在任一未关闭（或未按第 5 节正式豁免）的下列缺陷，**禁止发布**。此类缺陷不接受"下个版本修复"。

| 编号 | 阻断类型 | 判定标准（可观测） | 对应风险 |
|---|---|---|---|
| B-01 | 假成功 | 引擎任务失败但 Vivian 判定 success；或退出码 0 且无成功证据仍判 success | R-01 |
| B-02 | 配置损坏 | 任何一次正常运行/升级/回滚后用户配置无法被上游读取，或用户设置丢失 | R-03 |
| B-03 | 数据丢失 | 运行历史/审计记录在正常流程中丢失，或备份不可用 | R-03/R-11 |
| B-04 | 任意文件写 | 通过压缩包、路径、配置名使文件写入预期目录之外 | R-18/R-19 |
| B-05 | 管理员代码执行 | 低权限用户可借助 Vivian 的提权/更新链执行任意代码 | R-20 |
| B-06 | 孤儿进程持续操作 | 停止/退出/崩溃后引擎或游戏仍在注入输入且超过 30 s 未收敛 | R-04 |
| B-07 | 无法回滚 | 升级后 Smoke Test 失败且无法恢复上一可用版本 | R-12 |
| B-08 | 版本漂移未检测 | 引擎在用户机器上被静默更新后 Vivian 仍按旧规则运行 | R-02 |
| B-09 | 许可证违约 | 分发包缺少必要许可证/源码提供方式，或含禁分发组件 | R-31/R-32 |
| B-10 | 崩溃无法恢复 | 异常退出后重启必然进入不可用状态，需手工删目录 | R-16 |
| B-11 | 系统性误杀 | 正常长任务在无超时配置错误的情况下被强杀（≥1 次可复现） | R-07 |
| B-12 | 升级破坏回滚点 | 升级过程覆盖/删除 `_old` 或备份，导致回滚不可能 | R-11/R-12 |

**缺陷分级与门禁联动**

| 严重度 | 定义 | 发布影响 |
|---|---|---|
| Blocker | 命中 B-01~B-12，或核心功能完全不可用 | 禁止发布 |
| Critical | 主要场景失败需人工介入；无数据/安全影响 | 原则上禁止；需 CTO+QA 双签豁免 |
| Major | 部分场景失败、提示不清、性能不达标 | 可发布但须列入已知问题并在 2 个迭代内修复 |
| Minor | 文案/布局/边缘场景 | 可发布，记入 backlog |

## 4. G1 构建与供应链

| 检查项 | 证据 | 通过标准 |
|---|---|---|
| 可复现构建 | 构建脚本 + 两次构建产物哈希 | 哈希一致（允许时间戳差异，需说明） |
| 依赖锁定 | `packages.lock.json`/NuGet 锁定、Node 锁文件（如有） | 无浮动版本；CI 使用 `--locked-mode` |
| 引擎来源 | 官方 Release URL + SHA-256 记录 | 与 GitHub API digest 一致；下载后二次校验 |
| 自身产物哈希 | 安装包 SHA-256 | 公布于发布页；更新器校验 |
| 签名（V1 可选→V1.1 必须） | Authenticode 证书 | 未签名时必须明示"未签名构建"且禁止静默更新 |
| SBOM | 依赖清单（名称/版本/许可证/来源） | 完整；含三引擎若捆绑（模式 B） |
| CI 环境隔离 | 构建机无长期凭据 | 仅最小权限 token；OIDC/短期凭据优先 |

**阻断条件**：无法验证引擎包来源，或 CI 使用未锁定依赖 → 不得通过 G1。

## 12. 回滚预案（发布后）

| 触发 | 判定 | 动作 | 时限 |
|---|---|---|---|
| 发现 Blocker 缺陷（B-01~B-12） | 任一用户可复现 | 立即下架当前版本；公告；回退到上一稳定版 | 2 h 内 |
| 崩溃率 > 2%（启动后 10 min 内） | 遥测/用户反馈统计 | 暂停灰度；发布热修复或回滚 | 24 h |
| 假成功报告（用户反馈"没打却显示完成"） | 1 例即启动调查 | 冻结更新；提供手工回滚指引；修复后重新发版 | 立即 |
| 配置损坏报告 | 1 例即启动调查 | 停止自动更新；提供快照恢复工具 | 立即 |
| 许可证/合规质疑 | 法务确认 | 暂停分发；修订 NOTICE/源码提供 | 立即 |

**用户侧回滚流程（必须在 UI 与文档中可见）**：

1. 打开"引擎与更新"页 → 选择目标引擎 → "回滚到上一版本"。
2. Vivian 校验 `backups\` 中快照完整性 → 切换目录 → 恢复配置快照 → Smoke Test。
3. 若自动回滚失败，提供"从备份恢复"与"重新下载基线版本"两条路径，均不得要求用户手工删目录。

**发布侧回滚流程**：

1. 保留上一版本安装包与引擎包（至少 2 个版本）。
2. 回滚后必须验证：安装、启动、一次 dry-run、一次实机日常。
3. 回滚事件写入 `docs/acceptance/` 的发布记录。

## 14. 例外与豁免流程

1. 仅允许对 **Critical/Major** 申请豁免；Blocker（B-01~B-12）**一律不可豁免**。
2. 豁免必须包含：缺陷编号、影响范围、替代控制、到期日（≤ 1 个版本）、监控方式。
3. 审批：ARCH + QA 双签；涉及安全/合规加 SEC/LEGAL。
4. 豁免记录写入发布说明的"已知问题"，用户可见。
5. 到期未修复 → 自动升级为阻断，下一版本不得发布。
