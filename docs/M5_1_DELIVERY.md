# VIvian M5.1 开发与手动测试说明

基线：`claude/m5-daily-readiness` 的 `7d358c5`。M5.1 分支：`feature/m5-1-multi-account-safety`。本构建仍只允许固定版 March7thAssistant v2026.10.31 的星铁日常任务，每次真实任务需本人确认和处理 UAC。原神、绝区零只提供账号档案，不执行真实任务。

## 已实现

- 星铁“使用支援角色”映射到 `config.yaml` 的 `borrow_enable`；只修改此字段，保留角色、好友与搜索详情。原项目按钮打开已核对的主程序入口；该版本没有已核对的详细设置直达参数。
- 暂停和继续通过上游 `logs/runs/<run-id>.control` 协议发送，只有上游状态文件确认后界面才显示已暂停或继续。停止优先；暂停时调度器不计入任务与停滞超时。
- 分辨率失败熔断监看本次运行的上游日志。默认连续 2 次报“游戏分辨率获取失败”即向本次运行发送停止命令，并记录日志位置。可在 VIvian 数据目录的 `march7th-startup-limits.json` 配置：`{"maxResolutionFailures":2,"maxStartupWaitSeconds":180}`，合法范围分别为 1–5 次、30–900 秒。未取得运行编号而启动超时时只结束 VIvian 所拥有的进程，清理状态保持未确认。
- 现有 SQLite 升到 v5；升级前用 SQLite 在线备份生成 `vivian.db.pre-m5.1.bak`（从 v4 再升级则为 `vivian.db.pre-v5.bak`）并检查完整性。旧单账号数据保留为各游戏的“原有账号”。账号档案与星铁账号设置、任务计划、切换记录、逐账号执行记录、批次状态分表保存。不会保存密码或登录令牌。VIvian 档案删除需要两次确认，不删除游戏客户端凭据。
- 账号管理页提供添加、编辑、启停、排序、删除、星铁日常任务计划和批次历史。游戏管理页可以选择星铁账号；新增星铁账号必须绑定各自不同的 March7thAssistant 安装目录，完整的好友、队伍等上游详细设置留在该账号的原项目目录中。已登记参数另存到账号档案；批次运行前按字段临时写入所选安装目录，结束后按字段恢复。配置文件被持续占用时拒绝非原子覆盖。
- 星铁多账号批次按顺序运行。每位账号都需要手动登录，在游戏中核对所填 UID，并再次确认本次任务和临时配置差异。UID 未填写或身份未确认时不启动任务。普通失败可继续下一账号；临时配置未恢复或进程清理未确认时停止批次。支持停止批次、跳过当前账号；意外退出后的批次标记为中断，登录核对状态失效。
- AI 助手增加账号列表、账号独立设置和批次进度的只读工具。选中新增账号时阻止旧的共享配置修改提案写入。

## 自动化验证

- .NET 10 Debug 与 M5 Release 构建、xUnit 测试、WPF 启动和页面截图 smoke。
- 数据库迁移备份、账号档案增删改、隔离设置、批次中断状态、支援开关保留详情、精确运行编号控制文件、原有 M5 单账号回归。
- 模拟测试和 WPF smoke 均不等同于真实游戏测试。

## 请本人进行真实星铁测试

1. 备份当前 VIvian 数据目录，打开 M5.1 包中的 `VIvian.exe`。先在“引擎与环境”完成官方 v2026.10.31 发行包和安装目录核对。
2. 为新增星铁账号分别准备独立的官方 v2026.10.31 March7thAssistant 安装目录；不要把两个账号指向同一目录。在“账号管理”填写各自名称、区服、UID 和专属安装目录；启用“列入运行全部账号”与“账号任务计划：执行星铁日常”。原有账号继续使用“引擎与环境”的原安装目录。
3. 在“游戏管理”逐个选择账号，读取并保存各自任务设置。支援角色、好友和队伍详情在各账号的 March7thAssistant 原程序中设置。
4. 先对“原有账号”单独跑一次日常，确认原 M5 路径正常；再点“运行全部账号”。按弹窗逐个手动登录游戏、肉眼核对实际 UID，并确认每次运行及临时配置改动。
5. 观察暂停/继续、停止/跳过、账号结果与批次历史。若出现分辨率错误，确认第二次错误后停止且不再反复重启。把 VIvian 诊断包和上游本次 `logs/runs/<run-id>.log` 提供给开发者。

## 上游限制与残余风险

- 当前安装版文档提供精确运行编号的暂停/继续/停止协议，但未核实可靠的自动登录切换与实际 UID 读取接口，因此多账号使用人工登录交接，不能声称无人值守或机器验证登录身份。
- 每个新增星铁账号需要独立的上游安装目录；此版本不会自动复制包含敏感配置的原项目目录。未配置独立目录或多个账号引用同一目录时，该账号任务不会启动。
- 暂停、继续、分辨率熔断、批次切换仍需真实游戏验证；没有自动操作过用户游戏画质、显示分辨率、Windows 显示设置或登录会话文件。
- 对连续启动失败、重复窗口异常的通用熔断，以及更完整的启动前窗口/显示模式/运行依赖检查，尚需依据真实日志补齐。AI 不能直接启动批次，须由用户在账号页点击运行。
- 多账号队列的所有故障组合尚未完成模拟覆盖。建议先进行受控的 A/B 两账号实测，不启用无人值守。
