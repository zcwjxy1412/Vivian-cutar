## 1. 目标与范围

### 1.1 目标

1. 证明"调度器—适配器—引擎进程—游戏"这条链路在**成功、失败、中断、升级**四类路径上都可判定、可恢复、可解释。
2. 证明 Vivian 不会把"引擎失败"报告为"成功"（假成功是最高优先级缺陷）。
3. 证明更新与回滚不会损坏用户配置或使引擎不可用。
4. 证明安全边界（路径、参数、权限、供应链）在恶意输入下成立。
5. 给出可执行的发布门禁证据清单（见 `RELEASE_GATES.md`）。

### 1.2 范围内

- Vivian 进程内：状态机、调度、配置补丁、进程管理、日志聚合、更新器、UI 状态呈现。
- Vivian 与三引擎之间的契约：CLI 调用、退出码、日志/运行记录、配置文件、目录布局。
- 安装/更新/回滚的完整生命周期。
- 与 Windows 的交互：UAC、作业对象、会话结束、窗口焦点、热键。

### 1.3 范围外

- 三引擎内部算法正确性（由上游负责，Vivian 只做契约级验证）。
- 游戏反作弊对抗、封号风险评估（由用户与上游承担，Vivian 只做风险告知）。
- 游戏客户端的兼容性（游戏更新导致识别失效属已知外部风险 R-28）。

### 1.4 测试判定原则

| 原则 | 说明 |
|---|---|
| 否定证据优先 | 只要出现"失败/错误/异常/Traceback/取消"等否定证据，即使退出码为 0，也判定失败 |
| 端到端可解释 | 每个失败必须能回答"哪一步失败、证据在哪、用户该做什么" |
| 一次只变一个 | 故障注入用例必须单变量，避免归因困难 |
| 可重复 | 所有 A/S 级用例必须在干净环境可重复执行；M 级用例须记录机器、游戏版本、引擎版本 |
| 不做假设 | 任何"上游应该会……"的判断必须转为用例或标记为未验证 |

## 2. 测试策略

### 2.1 分层

| 层 | 内容 | 占比目标 | 执行频率 |
|---|---|---|---|
| L1 单元 | 状态机迁移、超时计算、日志规则、路径校验、配置合并、版本比较 | ~55% | 每次提交 |
| L2 集成（进程内） | 调度器 + 假引擎（FakeEngine）+ 临时目录 + SQLite | ~25% | 每次提交 |
| L3 契约 | 真实引擎二进制的 CLI/退出码/日志/配置文件（不启动游戏） | ~12% | 每晚 + 发版前 |
| L4 端到端 | 真实游戏 + 真实引擎 + 真实 UAC/焦点 | ~8% | 里程碑 + 发版前 |
| L5 破坏性 | 断电、强杀、磁盘满、恶意包、并发双开 | 专项 | 发版前 |

### 2.2 关键测试替身

1. **FakeEngine**：一个可配置的假引擎可执行文件，支持：
   - 按参数返回指定退出码（0/1/2/3/4/5/6/553/65535）；
   - 输出可编排日志（成功标志、失败标志、无标志、乱码、超大行）；
   - 模拟长时间运行、卡死、崩溃（非零退出/被强杀）、忽略 SIGTERM；
   - 生成 `logs/runs/<run_id>.json`（成功/失败/中断）与 `active.json` 锁；
   - 记录自己被调用的完整命令行到 `argv.json`（用于断言无注入）。
2. **GameStub**：一个假游戏进程（可被识别为 `YuanShen.exe`/`StarRail.exe`/`ZenlessZoneZero.exe` 名称的测试替身），用于验证"游戏存活判定"而不需要真实游戏。
3. **Clock**：可注入时钟，用于验证 45/40/30/180 分钟超时与 8 分钟静默超时，无需真实等待。
4. **FsHarness**：临时工作区 + 可控磁盘配额 + 只读目录 + 符号链接，用于路径与磁盘故障测试。
5. **NetStub**：可控 HTTP 服务（正常/慢速/断流/500/哈希不符/超大文件/路径穿越包），用于更新器测试。

### 2.3 环境矩阵

| 维度 | 取值 |
|---|---|
| OS | Windows 10 22H2、Windows 11 23H2/24H2 |
| 权限 | 标准用户、管理员、UAC 开启/关闭 |
| 路径 | 纯英文无空格、含空格、含中文、超长路径（>200 字符） |
| 磁盘 | NTFS 本地盘、非系统盘、剩余空间 <15 GB |
| 显示 | 1080p 100%、1440p 125%、4K 150%、双屏 |
| 游戏 | 已安装（三款）、仅安装一款、未安装、路径错误 |
| 网络 | 正常、限速、断网、代理、镜像不可达 |
| 引擎 | 基线三版本、更新一版、回滚一版、被篡改（改文件/改版本号） |

### 2.4 测试数据管理

- 所有测试使用独立的 `%TEMP%\vivian-test\<runId>\` 工作区，结束后保留失败现场 7 天。
- 不触碰用户真实 `D:\VivianWorkspace`；实机测试使用专用测试机与测试账号。
- 日志与截图入库前脱敏（见 T-90x）。
- 上游二进制只从官方 Release 下载并按 SHA-256 校验后入测试资产库。

## 3. 自动化实现要求

### 3.1 必须自动化的核心状态转换

以下迁移必须有单元测试（每条至少 1 个正向 + 1 个异常用例）：

| 编号 | 迁移 | 关键断言 |
|---|---|---|
| S-01 | Idle → PreCheck | 重复 Start 只产生一次迁移 |
| S-02 | PreCheck → ConfigPatching（通过）/ Blocked（失败） | 游戏缺失、路径错误、版本不兼容三条分支 |
| S-03 | ConfigPatching → StartingEngine | 补丁失败不得进入启动 |
| S-04 | StartingEngine → Running | 启动超时（30 s）转 Failed |
| S-05 | Running → CooldownCleaning（成功/失败） | 成功与失败都要清理 |
| S-06 | Running → Stopping → Idle（用户停止） | 停止超时升级为强杀并记录 |
| S-07 | CooldownCleaning → NextTask / Completed | 队列空/非空两分支 |
| S-08 | 任意 → Aborted（应用退出/系统关机） | 必须落盘可恢复状态 |
| S-09 | Failed（单游戏）→ NextTask（其他游戏继续） | 失败不污染队列（T-80x） |
| S-10 | Updating → Rollback → Idle | 升级失败可回滚（T-61x） |

### 3.2 必须自动化的失败恢复

- 崩溃恢复：进程在 Running 时被强杀 → 重启后进入"待对账"而非直接重跑（T-74x）。
- 配置自愈：配置文件被截断/写入非法 JSON → 从最近快照恢复并可启动（T-43x）。
- 更新回滚：注入"新版本 Smoke Test 失败" → 自动/一键回滚到 `_old` 并通过启动验证（T-61x）。
- 孤儿清理：强杀 Vivian 后，引擎与游戏进程在 30 s 内退出（T-42x）。

### 3.3 不得自动化的部分（必须人工）

- 真实游戏登录、进入游戏、完成一次日常（含过场/加载）。
- 真实 UAC 弹窗的用户交互与凭据输入。
- 真实窗口焦点被其他程序抢占时的行为。
- 真实显卡/驱动/分辨率切换后的图像识别效果。
- 断电/强行关机（需物理或虚拟化层面操作）。

上述项目列入第 6 节人工验收清单，未通过不得发布。

## 6. 用例集 B：引擎适配与"假成功"

> 本组是最高优先级。判定必须基于"退出码 + 结构化运行记录/日志 + 进程存活"三通道，且否定证据一票否决。

| ID | 场景 | 风险 | 级别 | 步骤（摘要） | 预期结果 |
|---|---|---|---|---|---|
| T-011 | BGI 传错配置名 | R-01 | S | 用不存在配置名调用；观察上游行为 | Vivian 预先校验配置名存在；不存在则拒绝启动（不得静默跑默认配置） |
| T-012 | BGI 日志"一条龙和配置组任务结束"但存在 FATAL | R-01 | A | 构造日志：结束标志 + `UnHandle Exception [FATAL]` | 判定 failed；UI 展示 FATAL 行；不得因结束标志判成功 |
| T-013 | BGI 日志含"任务被取消，退出执行" | R-01 | A | 构造取消标志，退出码 0 | 判定 cancelled/stopped，不是 success；不触发"今日已完成" |
| T-014 | BGI 结尾无结束标志（进程 0 退出） | R-01 | A | 退出码 0、日志无结束标志 | 判定 failed（证据不足）；提示检查日志 |
| T-015 | ZZZ 退出码 0 但内部任务失败 | R-01 | A | 父进程 0 退出，日志/后端状态为失败 | 判定 failed；需读取后端/运行记录证据，不能只看退出码 |
| T-016 | ZZZ 父进程 0 退出、子进程仍在跑 | R-04 | S | 模拟 `pyuac` 分离 | Vivian 追踪子进程与游戏进程；任务未真正结束前保持 Running；超时后按策略处理 |
| T-017 | M7A 退出码 0 但 run.json 为 failed | R-01 | A | 写 `logs/runs/<id>.json` status=failed | 判定 failed；以运行记录为准，文本"已完成"不得覆盖 |
| T-018 | M7A 退出码 3（首次运行未完成） | R-10 | A | 退出码 3 | 判定 blocked；UI 引导打开 M7A Launcher 完成首次设置；不重试刷屏 |
| T-019 | M7A 退出码 6（被停止） | R-01 | A | 退出码 6 | 判定 stopped；不计入失败率 |
| T-020 | 退出码 553/65535/0xC000013A | R-01 | A | 分别注入 | 553=提权未完成（提示管理员启动）；65535=单实例冲突（提示关闭已有实例）；0xC000013A=被中断，判定 failed/interrupted 而非 success |
| T-021 | 中文 JSON 转义解析 | R-08 | A | M7A 输出 `\u5df2\u5b8c\u6210` | 正确解码为"已完成"；不误判、不乱码 |
| T-022 | 日志多实例标识 | R-08 | A | BGI 日志含 `[BgiInstance] GP:S1:P123:T...` | 只摄取本次实例行；其他实例行被忽略；不串日志 |

| T-024 | 引擎启动后立即退出（0 秒） | R-01 | A | FakeEngine 立即 exit 0，无日志 | 判定 failed（无成功证据）；提示"引擎异常退出" |
