# VIvian V1.0 风险登记册（RISK REGISTER）

| 项目 | 内容 |
|---|---|
| 版本 | v1.0（审查基线） |
| 基准日 | 2026-11-03 |
| 关联文档 | `docs/reviews/ARCHITECTURE_REVIEW.md`、`docs/acceptance/TEST_PLAN.md`、`docs/acceptance/RELEASE_GATES.md` |
| 评分法 | 可能性 P（1~5）× 影响 I（1~5）= 风险值 R；R≥15 高、8~14 中、≤7 低 |
| 责任角色 | ARCH=架构组，QA=质量保证，SEC=安全，LEGAL=法务/合规，OPS=发布运维 |

> 风险登记册是活文档：每次 Spike/实机验证后更新"状态"（Open / Mitigating / Accepted / Closed）与证据。

## 3. Top-5 风险响应计划

### R-01 假成功（R=25）

- **短期（Spike 内）**：为三引擎各写一个"失败注入"用例，确认当前判定逻辑的误判率；产出 `EngineOutcome` 契约与"否定证据"清单。
- **中期**：适配器只输出结构化 outcome，UI 不再直接读退出码；ZZZ 增加"后端/日志 + 游戏进程"双证据。
- **关闭标准**：TEST_PLAN T-05 全部用例通过，且连续 20 次实机运行 0 误判。

### R-02 版本漂移（R=20）

- **短期**：确认 ZZZ `env.yml` 写入后 `git HEAD` 稳定；BGI 固定 tag。
- **中期**：引入"引擎指纹"（版本 + 关键文件哈希 + CLI 探针结果），写入数据库并随每次运行校验。
- **关闭标准**：连续 3 次启动指纹一致；人为篡改 `src` 被拒绝启动。

### R-03 配置损坏（R=20）

- **短期**：确认三引擎配置文件在"引擎未运行"时写入可稳定生效；确认 M7A 只改 `check_update` 即可。
- **中期**：配置补丁协议（快照 → 锁 → 写 → 回读 → 校验）；补丁清单版本化。
- **关闭标准**：并发写 100 次无损坏；补丁后三引擎各完成一次 dry-run。

### R-04 孤儿进程（R=20）

- **短期**：实测 Vivian 提权后三引擎是否二次弹 UAC；确认 Job Object 能覆盖 `pyuac`/`runas` 子进程。
- **中期**：引擎身份登记 + 停止确认 + 启动时清理残留。
- **关闭标准**：强杀 Vivian 后 30 s 内引擎与游戏退出；"停止"按钮 10 s 内生效或给出明确选择。

### R-05 供应链（R=15）

- **短期**：只允许 GitHub 官方域；记录 API digest 并与下载文件比对。
- **中期**：项目签名清单 + 低权限解压/探针 + 用户确认。
- **关闭标准**：恶意样本 100% 拒绝；未签名包必须人工确认且默认不执行。

## 4. 风险接受与升级规则

1. **不得单方面接受** R≥15 的风险；需 ARCH + QA +（安全类）SEC 三方签字。
2. 任何"接受"必须有到期日与复审条件（如"上游发布新版本后 30 天内复审"）。
3. 出现以下情况立即升级为阻断：假成功被实机复现、配置损坏可复现、任意文件写被证实、管理员代码执行被证实。
4. 风险状态每次迭代更新；发布前由 QA 核对"高风险的缓解措施均有对应用例"。
