# 首页按原因处理错误

## 用户要求与实现

首页按实际原因提供对应操作，不把所有错误都送到桌面清理：

- 桌面交接、临时配置：沿用现有恢复流程及其确认门禁。
- 普通待清理运行：在首页确认游戏、引擎和输入宿主均已退出后，调用现有调度器登记；原神协议恢复仍单独处理。不会把失败结果改为成功或自动重跑。
- 未应用的星铁任务配置：直接调用现有交互式保存流程，失败继续保留入口。
- 安装目录：仅处理一个有问题的引擎；BetterGI 专用提示仅处理原神。优先核验当前或已保存目录，缺失时打开目录选择。失败恢复原路径，核验通过才保存；没有自动下载或替换引擎。
- 安装配置版本冲突：确认放弃未保存路径后重新读取已保存版本。
- 其他异常：显示原因并生成本地诊断报告，明确不等于自动修复成功。账号缺失仍打开对应选择入口，不猜测账号。

提示栏只保留一个按原因变化的轻型蓝金圆角按钮；无动作时显示“检查状态”。首页左右内容区及导航栏隐藏滚动条但保留滚动。按钮保留键盘焦点、禁用状态、忙碌防重复与异步等待。

## 验证与审查

实际 WPF 隔离渲染覆盖窄宽窗口与 DPI 矩阵、命令分流、防重复、忙碌禁用、失败后保留操作。新增无效引擎候选路径检查验证失败不替换当前或已保存路径。没有对正式账号启动游戏。

DeepSeek 首审指出安装路径处理范围过大、失败候选残留、泛化 ArgumentException 导航不准确。已删除硬编码目录发现、限制单引擎范围、恢复失败候选、将未知参数异常归入诊断。首审关于忙碌时按钮无反馈的建议经核对不适用：窗口及父容器在忙碌时均禁用，代码另有同样门禁。

复审及最终安装校验记录见本次 artifacts 与回滚目录 verification.json；未取得复审结果前不标记独立审查通过。
