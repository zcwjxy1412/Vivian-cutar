# M5 固定测试版与反馈闭环

> 历史记录（2026-11-06）：以下描述旧 M5 固定部署流程。当前 M5.2 的账号批次与操作以 [M5_2_DELIVERY.md](M5_2_DELIVERY.md) 为准；当前目录、CI与归档策略见 [CLEANUP_2026_11_08.md](CLEANUP_2026_11_08.md)。旧步骤保留供回滚追溯。

## 用户操作

双击 `E:\auto agent game\VIvian\VIvian.exe` 或桌面“VIvian（开发测试版）”。程序启动时尝试复用已保存的路径，检查已知安装、星铁官方 ZIP 和配置，并显示三个引擎的兼容状态。缺少 OneDragon 不影响 VIvian 启动。启动不会执行游戏任务；星铁 `daily` 仍须在首页逐次确认，UAC 由本人决定。

出错时截图并告诉 Codex 检查 `E:\auto agent game\截图反馈`。每次启动生成 `对应日志\会话-*.json`，首页显示会话 ID。真实任务结束后自动导出脱敏诊断包；“保存反馈”可随时再次生成。截图请放入 `待处理截图`，用户不必手工寻找 RunId 或日志。

## Codex 更新步骤

在当前独立分支提交源码后运行 `scripts/Deploy-M5Local.ps1`。脚本执行 M5 全量 xUnit、win-x64 自包含发布、暂存目录和固定目录两次 WPF 冒烟、只读的正常启动检查，成功后更新桌面快捷方式。若固定版正在运行，脚本停止更新。旧版移动至 `项目归档\VIvian-<UTC 时间>`，异常时尝试回滚；不删除旧版或独立数据目录。

CI 继续构建默认版和 M5 专用包，上传 Artifact 作为备份。M4 历史测试类型保留在 CI，但每次 M5 提交不再重复上传旧预览包与探针。

## GitHub 整理边界

PR #46、#47、#48 仍有独立审查价值，依赖顺序为 #46 → #47 → #48 → 本轮 PR；保留全部分支和未合并提交。本轮只精简新 PR 的 Windows CI：功能分支由 PR 事件触发一次，`main` 推送仍触发；只上传默认包、M5 包和诊断证据，保留期分别为 30、30、14 天。

**待确认后才可永久清理：**旧 CI 运行中重复的 M4 预览/探针 Artifact、已由正式版本取代的远端分支、历史 Release 和不再引用的旧脚本。本轮不删除这些远端对象，也不改写 `main` 历史。
