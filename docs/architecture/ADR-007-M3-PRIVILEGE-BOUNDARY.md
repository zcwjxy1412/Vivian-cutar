# ADR-007：M3 权限与进程身份边界（待验证）

状态：**提案 / 不允许据此启用生产适配器**。关联 [Issue #16](https://github.com/zcwjxy1412/Vivian-cutar/issues/16)、[M3 前置清单](../M3_PREREQUISITES.md)。

## 已知边界

VIvian 当前清单为 `asInvoker`。M2 的 `WindowsProcessSupervisor` 使用 `CreateProcess` 挂起子进程、加入 Job，再恢复。它只保证**直接创建且成功加入同一个 Job 的进程**可由 VIvian 清理。上游如果自行 UAC 提权、经服务/启动器创建新进程，当前 Job 不自动涵盖它们。不得因为根进程退出、退出码为 0 或 Job 空了，就报告真实日常已完成或所有相关进程已清理。

## 提案与失败策略

1. UI、设置和查询保持普通权限。只有经固定版本证据证明需要提权的执行动作，才考虑专用执行器；正常 Windows UAC 必须由用户亲自确认。
2. 执行器必须在建立身份与清理协议后才能启动真实引擎：运行 ID、进程 ID 与创建时间、Job 归属、事件源及停止回执均需关联同一次运行。跨权限通信的请求必须限制为预定义动作和路径，不执行任意命令。
3. UAC 被拒绝、执行器身份无法核实、子进程脱离 Job、停止回执或进程树不完整时，判定结果未知/清理未确认并阻断下一任务。不能按进程名强制清理。
4. 无法为某引擎证明安全的生命周期控制时，其适配器只能提供只读状态与“打开原生界面”；不能把“已启动”或“退出”呈现为任务完成。

这是待实测的设计约束，**尚未决定**提权执行器具体实现，也没有改变 M2 的调度器或默认权限。

## 无害进程验证矩阵

| 场景 | 机器 | 应保存的证据 | 通过门槛 |
|---|---|---|---|
| 普通权限启动 FakeEngine，并派生测试子进程 | Windows CI、桌面 | 权限级别、PID/创建时间、Job 活跃数、退出与清理记录 | 子进程都在所属 Job，停止后归零 |
| 执行器请求 UAC，被用户拒绝 | 桌面 Windows 10/11 | UAC 选择、返回码、运行记录 | 未启动引擎；结果未知或明确取消；下一任务不会误启动 |
| 被提权的无害进程启动子进程 | 桌面 Windows 10/11 | 两边权限、进程树、Job 归属 | 无法证明归属则显示清理未确认并阻断 |
| UI 崩溃或被强制结束 | CI 可测同权限路径；提权路径需桌面 | 前后 PID、Job 状态、重启对账 | 未残留受控进程；未知状态不改写为成功 |
| 执行器被强制结束、停止超时 | 桌面 Windows 10/11 | 停止回执、进程树、数据库状态 | 不能确认清理时阻断下一任务 |
| 用户手动打开同名引擎 | 桌面 | 原程序 PID/路径与测试 Job | 只阻断冲突，不终止原程序 |

每次记录系统版本、完整命令、运行 ID、原始日志、时间戳和必要的文件摘要；测试账号与配置不得提交仓库。CI 是 Windows Server，无法代替桌面 UAC 人工验收。任何真实游戏启动须另行获得用户明确授权。

## 待决事项

- 提权执行器与普通权限 UI 的通信/认证及生命周期协议。
- 引擎经 ShellExecute、服务或独立启动器产生的进程如何辨别与停止；不能证明则缩小支持范围。
- 完成 #16 的无害进程原型与桌面实测后再将此 ADR 改为 Accepted 或 Rejected；按引擎固定版本独立审查。
