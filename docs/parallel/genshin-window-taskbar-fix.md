# 原神窗口与任务栏闪烁反馈

用户确认现象为整个任务栏反复出现、消失或闪一下，而非图标提示。两次正式计划均在两个星铁账号完成后，首个原神账号登录识别失败，尚未交给 BetterGI 执行任务。失败记录为“原神窗口不在前台，或客户端身份已经变化”，不能从旧记录进一步区分实际前台丢失、窗口替换或采集时几何变化。

## 本次修改

- 原神 Prepare 原先每 450ms 可调用共享 BringToFront，反复 TOPMOST→前台→NOTOPMOST。现每次启动准备最多一次普通恢复/前台请求，不切换置顶状态、不修改任务栏设置，也不改星铁的共享激活逻辑。
- 采集结束时仍要求同一 HWND、PID、启动时间和前台来源。仅同一客户端的位置或尺寸变化时丢弃本帧全部坐标、账号行及 UID 证据，返回 Unknown 供有超时且带轮询间隔的流程重新采集；真实失去前台或身份变化仍停止。交接确认仍不接受 Unknown。
- 原始登录失败详情从精确子批次记录读取，在首页展示游戏、账号及后续未执行数量；提供只读的失败详情弹窗。清理门禁保持，异常拦截文案保留原始原因。

旧隔离历史库 schema 7 与当前 schema 8 的读取不兼容，会产生独立的历史刷新警告，不是本轮登录失败的直接原因。本次未迁移旧库或清除历史记录。

## 验证与审查

针对性 51/51：一次前台请求、300 次等待不重复请求、同客户端几何变化丢弃旧证据后重新读取、真实身份变化拒绝，以及过期/错误引用/无窗口输入帧在任何原生窗口或输入调用前拒绝。真实 WPF 测试验证子批次原因显示和按钮分类。

DeepSeek 两轮。采纳补齐输入拒绝路径测试。首审“无界轮询”经核对不成立：已有 CancelAfter 和生产 450ms 间隔；窗口标题生产固定为空，输入与读取由单一驱动串行调用。复审无阻塞项。其“早返回保留旧状态”推测不成立，辅助方法首先无条件调用 SetPersistentPlanCompletion；数据库读取使用默认不取消令牌且自己拥有连接；详情弹窗只在主窗口空闲时由用户点击，不持有执行门禁。无经核实遗留实现问题。

这修复了可验证的反复置顶路径及几何变化误判，但没有重新启动真实游戏，不能声称任务栏现象已通过实机复测。登录失败后的清理状态传递由执行分支单独修复、审查和合流。
