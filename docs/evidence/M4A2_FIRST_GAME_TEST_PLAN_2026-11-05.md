# M4-A2 首次星铁真实任务方案（待用户另行批准）

## 候选任务

固定上游 March7thAssistant v2026.10.31 的 `screen_test`（界面可切换性测试）。该任务在官方 `utils/tasks.py` 白名单和 `main.py` 分发中存在：上游先调用 `game.start()`，随后遍历可达游戏界面，逐项记录切换成功或失败，最后输出成功、失败和总数。它不会主动执行“清体力”或“每日实训”，但会操作游戏界面；界面切换路径的实际副作用尚未经本机验证，不能保证账号状态完全不变。上游可能按个人设置写入日志、配置、错误截图或遥测，游戏可能在任务结束后继续打开。

本次仅运行一个 `screen_test`，参数固定为 `screen_test --after-finish None --json`。不使用 `--force`、`--detach`、自动重试、循环、定时计划或下一任务。上游会请求 UAC，由用户本人核对并确认。VIvian 必须在本次界面确认后才可启动。

## 观察与停止

VIvian 捕获本次上游 RunId 和日志。停止时仅向 `--control <该 RunId> stop --json` 发送指令；回执 `acknowledged=true` 只代表收到停止要求。随后核对本次终态记录、Worker 的 PID/创建时间以及 VIvian 自身 Job 的清理。任何记录缺失、权限拒绝或 Worker 仍在运行均保留 `CleanupState.Unconfirmed → Indeterminate → Blocked`，不按名称结束进程。

只有本次运行的输出同时具备正数的界面总数、每个界面依序成功切换、零失败和一致的结束计数，且同一 RunId 的上游终态与退出码匹配时，代码才生成完成证据。仅有退出码 0 或上游 `success` 保持结果未知。此规则目前只经代码测试，真实上游日志格式仍待本次实测。

## 必须先满足

1. 用户核对游戏账号和上游设置，自行决定是否接受游戏自动化的账号风险，以及界面切换可能导致的未知副作用。
2. 用户明确批准这**一次**真实游戏任务和一次 UAC 提示；由用户亲自处理 UAC。
3. 运行前确认固定版安装身份，并调用上游 `m7a.exe --status` 检查本次任务未与已有上游任务冲突、游戏路径有效。该状态查询可能在上游目录创建并删除短暂的写权限探测文件；若不满足或状态进程清理不明，停止在预检阶段。
4. 使用独立 VIvian 数据目录，原有 0.4.0-dev 安装及 SQLite 不受影响。

若首次测试只验证启动与停止，则在任务开始后由用户决定何时按“紧急停止”。若观察完整完成，则保留本次日志与报告并对照实际游戏界面；软件的完成判定不能代替用户对账号结果的确认。测试后逐项核对 Worker 与子进程，结果不足时不开启下一任务或自动调度。

这份方案不构成当前运行授权。真实执行闸门在获得上述批准并完成专用单次构建之前继续关闭。
